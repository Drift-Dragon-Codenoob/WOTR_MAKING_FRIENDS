# Synthesist runtime implementation and acceptance report

Updated 1 November 2026. Branch: `synthesist`. **Development candidate; the complete archetype is not accepted for release.** Keep the existing mod ID. Version 0.3.0 and its distribution archive are reserved for the candidate that passes the full in-game matrix.

## Character-build flow checkpoint - 1 November

**Two player attempts failed:** creation displayed the acquired build-start feature but no evolution/appearance steps. The first repair linked `Next`, which was insufficient. Further inspection found the actual presentation mismatch: CharGenVM creates normal pages only for `Parent == null`, while its nested picker requires an item that supports nesting. Our choice items are plain features, so parented states remain hidden. The replacement adapter appends normal root selection pages instead. Assembly checks cover the null parent argument and the installed native page filter. A bounded passive log records the first transition of each kind. David's retest is pending; the character-build UI is not accepted yet.

David now performs all in-game tests. This checkpoint uses source inspection, compilation, pure rules checks, installed-assembly metadata inspection and archive extraction only. It does not install, launch, control or exercise WotR.

The candidate adds **Build your eidolon** native selections at every Summoner level, including creation and respec. Players can rebuild their evolution allocation or retain an existing saved allocation and spend remaining points. Aspect allocation precedes eidolon allocation when available, so its aggregate diversion is visible before spending the eidolon's balance. Native dependent selections continue after each purchase, then require appearance and a final review. Finishing with unspent eidolon points requires a separately labelled confirmation. Selected choices stay valid in their original slots after consuming their points; later slots still enforce current costs and prerequisites.

A separate serialised build part owns the draft and confirmed purchase ledger. Native preview edits contain no canonical entity references. Native commit replays selections, then applies confirmed purchases to the existing canonical entity once per build revision. Rebuilding preserves free form grants and wound/recovery records. Runtime preparation purchases/reset update the saved ledger so subsequent level-up does not silently revert a retrained build. Native cancellation/backtracking/respec still require David's tests; these are implementation paths, not verified gameplay claims.

There are ten cosmetic candidates: Incubus, Succubus and Movanic Deva for biped; Hellhound, Nightmare, Manticore and Vavakia for quadruped; Marilith, Lillend and Salamander for serpentine. Selection uses model portrait icons and descriptions. Form and arm compatibility are enforced; only Vavakia is offered as an armed quadruped candidate. Source prefab choice supplies no subtype package, statistics or mechanical limbs. The same saved choice supplies the fusion buff's visual and the canonical eidolon's native custom-prefab field; post-load reconciliation reapplies it. The canonical body enables hands when appropriate arms exist. Preparation has a compatible cosmetic appearance menu without reopening evolution allocation. **Animations and native UI have not been tested. A separate animated 3D preview screen is not implemented.**

Canonical eidolon feats, skills and native HD advancement remain in the pet's level-up interface during preparation. Fusion checks that this advancement is finished. Evolution and appearance choices are now part of protagonist creation/advancement; pet feat/skill choices have not been moved onto those screens.

The player candidate uses `SynthesistPreview=true` to register the development archetype without compiling the automated acceptance/profiling interface. Ordinary production builds retain the closed registration gate. The pending isolated DR/alignment implementation is included and receives build-menu choices; no new native damage-test pass is claimed. The earlier identifier warning was a comparison-script defect: ordinal dictionary comparison preserves every existing source identifier, including case-distinct names.

Offline results: 873 baseline assertions, 10,083 Synthesist rules assertions, 154 character-build assertions, 6,324 assembly/source checks and 1,274 build-flow assembly/identifier checks pass. The player build compiles with zero warnings/errors. ZIP validation checks root-level metadata/DLL, portable paths and matching hashes after both .NET and Unity Mod Manager Ionic.Zip extraction. These results do not accept Unity UI, models or lifecycle behaviour.

The archive and the short, creation-first handoff are generated by `scripts/Build-SynthesistPlayerCandidate.ps1`; see [the player test instructions](SYNTHESIST_BUILD_FLOW_TEST.md). The installed mod, saves, loader configuration and running-game state are untouched by this checkpoint.

## Approved target

Use the original PF1e APG Summoner and Ultimate Magic Synthesist, with the protagonist retained as the same entity. Use eidolon temporary HP and optional Fused Link, initially off. Preserve wounds through dismissal, loading and rest. A slain eidolon returns no earlier than the following day, at half HP after its ritual. There is no combined-HP pool, automatic 2-HP rescue or automatic rest recovery.

The original three forms, original HD/BAB/evolution table and three ability increases at Summoner levels 5, 10 and 15 are the target. Preserve Aspect and Greater Aspect; include Split Forms at 16 and original Twin Eidolon at 20 in the first playable candidate. Level-up/respec and other transformations require dismissal for the initial release.

David's normal configuration is the primary compatibility target: ToyBox unlimited spellcasting and combined after-combat spell/ability restoration enabled, with Respec Mod and ModMenu installed. After-combat ability restoration must preserve eidolon wounds, personal HP payments, death recovery and closed evolution allocation.

Decisions confirmed during implementation:

- The baseline eidolon pet strip provides selection and inventory access.
- If an independent eidolon is alive at non-positive HP when Split Forms ends, rejoining supplies no positive temporary HP and sends it away as slain. It does not rescue the Summoner.
- **Climb, swim and underwater-breathing evolutions are unavailable for now.** No replacement map movement or check bonuses have been invented. The original-rules reference table retains the tabletop entries, while native grants omit the unavailable capabilities.
- **Unknown spell components remain usable until verified.** Confirmed somatic spells require appropriate limbs. The catalogue retains `unknown` separately from a verified absence of somatic components, so later verification can tighten the guard without misrepresenting the source.
- **Eidolon class skills use the approved WotR mapping:** Perception, Stealth, Persuasion and Knowledge (Arcana), plus four different permanent choices from the remaining seven native skills. Craft has no native equivalent. The initial preparation level-up owns these choices, the first feat and skill ranks; evolution retraining does not reset them.

## Implementation in the working tree

The rules layer covers all twenty eidolon rows, base forms, the archetype grant/removal identities, wound and Fused Link transactions, death-day eligibility, mode transitions and native-resource budget interfaces. Native resources now determine ability availability; independent expenditure counters were removed from `FusionState`.

The runtime candidate adds native archetype registration, an isolated d10/full-BAB eidolon class and form-specific native save profiles; a serialised `UnitPartSynthesist` with a native canonical entity reference in cross-scene storage; preparation and allocation controls; separately owned projection facts/modifiers; fusion, dismissal, Melds, Jump, Split and Twin controls; native resources; an optional reflection-based ToyBox after-combat adapter; and initial level-up/respec protection. Rejuvenate spells use a separate spell list/book and native healing rules. Maker's Jump uses native Dimension Door delivery.

These systems are under integration testing. Their presence in source is not evidence that their complete gameplay behaviour is correct. Startup validation has already caught shared mutable evolution components; copies are being isolated before any per-archetype changes are applied. Ordinary Summoner regression testing remains required.

An internal acceptance build (`-p:SynthesistAcceptance=true`) includes the fixed test interface restricted to `SYNTHTEST-` characters. The player candidate instead uses `-p:SynthesistPreview=true`: it offers the development archetype with that interface and profiling hooks absent. Normal production builds contain no active command interface and do not offer the unfinished archetype. Internal direct fusion entry does not test the one-minute action itself.

## Remaining release gates

The handover save enabled reproduction of the combat slowdown. An inherited-menu cleanup loop repeatedly raised native ability-removal events for action-bar-retained abilities, rebuilding the entire action bar every frame. The targeted repair and measured results are recorded in [the performance report](SYNTHESIST_PERFORMANCE.md). This is a separate repair checkpoint; the full gameplay matrix below remains outstanding.

Finish and verify the original evolution catalogue, prerequisites, costs and ownership; natural/manufactured attack assembly; arms/model compatibility; exact statistics, size and equipment behaviour; somatic catalogue handling; ordinary/eidolon healing and Constitution changes; effect-state reproduction in Split Forms; native resource/timer persistence; original Twin racial-trait handling; respec completion/cancellation/removal; and the complete acceptance matrix from the approved plan.

Improved natural armour's fifth purchase and the original managed-evolution level gates use separate native purchase facts. Fast healing has separate native 1-5-HP buffs, with personal healing while fused and independent eidolon healing only during Split Forms; fast-healing purchases and native timed healing still need acceptance. Initial/advancement evolution capacity is refreshed without changing daily combat resources or opening a closed allocation.

Split Forms projects managed ability-score and natural-armour evolutions onto the Summoner without importing the eidolon's physical base values or advancement armour. Aspect overlap is counted once; native natural armour is a stacking descriptor. The targeted physical-statistic/armour purchase sequence passes on the biped fixture. Split-created effect copies are tracked separately, retained across an active split load, and cleaned up on rejoining/dismissal to prevent accumulating copied buffs. Reproducing arbitrary effect component counters and reconciling effects acquired independently during a split remain release gates.

The native purchase sequence found and repaired two Growth faults. Its copied size restriction read the ordinary evolution rank, preventing the isolated Synthesist Huge upgrade; that restriction now accepts an optional owned rank reference while retaining the ordinary default. Native size already changes reach from five feet to nine/twelve feet for Large/Huge. Growth now adds only the correction needed for the original form-specific reach. The first conversion incorrectly treated those table values as increases; the retained failed run caught this and the corrected candidate passes canonical/fused/split reach checks. Independent reach modifiers are not removed. Native non-biped and ordinary Summoner reach acceptance remain outstanding.

Preparation now synchronises the inactive canonical entity's displayed damage from the authoritative wound ledger before activation. The original fixture contained an older native HP snapshot; entering preparation must display its 98 recorded wounds without healing or changing that ledger.

Mental ability increases on the canonical eidolon no longer project onto the fused Summoner: Fused Eidolon explicitly retains personal Intelligence, Wisdom and Charisma. Split Forms shares all purchased evolution effects between the independent creatures; Twin copies the evolution effects onto the personal base scores. The three-mode native purchase test passes; its evidence is under `artifacts/runtime-mental-evolutions/`, with merged candidate SHA-256 `3442261902CA8220F2D981F5AF0C16EF40E45C08762BC346DA2F11160D53EB4B` retained under `artifacts/mental-evolution-candidate/`.

`scripts/Invoke-SynthesistProbe.ps1` provides the bounded native test interface. `tests/Verify-SynthesistRuntime.ps1` passes the targeted 13-check damage/healing/repeated-transition sequence; `tests/Verify-SynthesistEvolutions.ps1` passes the targeted 44-check native purchase sequence. Evidence is retained under `artifacts/runtime-durability-reach-fixed/` and `artifacts/runtime-evolutions-reach-total-fixed/`; the tested merged candidate is retained under `artifacts/growth-reach-total-candidate/` (SHA-256 `AEFAD8901F7F885781F4EB444C63B1692A3138D41FA2793F3AF02BCE6B2CCEC7`).
